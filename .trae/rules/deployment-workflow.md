# Deployment & Workflow

## Build Process

### Pre-deployment Checklist

```sh
# 1. Run TypeScript and Astro checks
bun run check

# 2. Build for production
bun run build

# 3. Preview the build locally
bun run preview
```

### Build Output

- Target directory: `./dist/`
- Static site generated by Astro
- Optimized for Cloudflare Pages CDN

## Cloudflare Pages Configuration

### Wrangler Setup

Configuration in `wrangler.jsonc`:

- Project name: `flugblattgestalten-de`
- Production branch: typically `main`
- Build command: `bun run build`
- Output directory: `dist`

### Environment Variables

- Set in Cloudflare dashboard or `.dev.vars` (local only)
- **Never commit** `.env` or `.dev.vars` files
- Document required env vars in README if adding new ones

### Deployment Commands

```sh
# Deploy to production (from main branch)
wrangler pages deploy dist

# Preview deployment
wrangler pages deploy dist --branch=preview
```

## Git Workflow

### Before Committing

1. Run `bun run check` to catch TypeScript/Astro errors
2. Test changes locally with `bun run dev`
3. Verify build succeeds: `bun run build`
4. Preview production build: `bun run preview`

### Commit Messages

Follow conventional commits format:

```
feat: add new contact form section
fix: correct hero image alignment on mobile
style: update spacing in mission section
content: update landing page copy
chore: update dependencies
```

### Branch Strategy

- `main` → production (auto-deploys to Cloudflare)
- Feature branches → preview deployments
- Keep branches short-lived

## Dependencies

### Installing Packages

```sh
# Always use Bun
bun add <package-name>
bun add -D <dev-package>

# ❌ Don't use npm/pnpm/yarn
```

### Updating Dependencies

```sh
# Update all dependencies
bun update

# Update specific package
bun update <package-name>
```

### Lock File

- `bun.lock` is committed to the repository
- Ensures consistent installs across environments
- Regenerate if corrupted: delete and run `bun install`

## Performance Monitoring

### Build Performance

- Monitor build times in Cloudflare dashboard
- Keep builds under 2 minutes
- Optimize images before committing

### Runtime Performance

- Lighthouse scores should be 90+ on all metrics
- Test on real devices, not just desktop
- Monitor Core Web Vitals in Cloudflare Analytics

## Troubleshooting

### Build Failures

1. Check TypeScript errors: `bun run check`
2. Verify Node version: `node -v` (should be ≥22.12.0)
3. Clear cache: delete `node_modules`, `dist`, `.astro` and reinstall
4. Check Cloudflare build logs for specific errors

### Asset Issues

- Images not loading: check file paths are correct
- Styles not applied: verify token imports in `global.css`
- 404 errors: ensure files are in `public/` or `src/assets/`

### Wrangler Issues

```sh
# Login/re-authenticate
wrangler login

# Check current deployment status
wrangler pages deployment list

# View deployment logs
wrangler pages deployment tail
```

## Security

### Content Security

- Validate all external links before deployment
- Sanitize user inputs if adding forms
- Use HTTPS for all external resources

### Access Control

- Limit Cloudflare dashboard access to team members
- Use API tokens for CI/CD, not account credentials
- Rotate tokens periodically

## CI/CD (Future)

When setting up automated deployments:

- Use GitHub Actions or Cloudflare's Git integration
- Run `bun run check` in CI pipeline
- Block merges if checks fail
- Auto-deploy main branch to production
- Preview deployments for PRs
